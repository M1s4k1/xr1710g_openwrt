## 8. 脚本编写约定（血泪教训）

本仓库脚本经历过三次同类事故，务必遵守：

1. **变量插值后紧跟非 ASCII 字符时，必须用 `${VAR}` 花括号界定**
   ```bash
   echo "写入 $STAMP，已完成"      # ✗ set -u 下报 STAMPï¿½: unbound variable
   echo "写入 ${STAMP}，已完成"    # ✓
   ```
   原因：bash 会把后续多字节字符的首字节并入变量名解析。

2. **不要在 `echo` 里用全角括号 `（）` 包裹变量插值** —— 同上，改用 ASCII `-` 或空格。

3. **`grep -E` 里用 `[[:space:]]` 而非 `\s`** —— BSD/GNU 对 `\s` 支持不一致，macOS 上会静默失效。

4. **不用 `mapfile`** —— macOS 自带 bash 3.2 无此内建，改 `while IFS= read -r`。

5. **`grep -E` 里也不要用 `\b`** —— BSD grep 的 ERE 同样不支持（第 4 次同类事故）。
   词边界改用「非字符集」表达方式，例如 MAC 检测写：
   ```bash
   (^|[^0-9a-fA-F:])(00:58:28:...)      # ✓ 跨平台
   \b(00:58:28:...)\b                   # ✗ macOS 上静默零命中 ⇒ 检测假通过
   ```

> 排查工具：`python3` 扫 `\$(\w+)(?=[^\x00-\x7F])` 可定位第 1 类隐患。
